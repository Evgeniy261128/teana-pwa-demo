# Правила разработки для AI-агентов (Antigravity)

Этот документ является **обязательным контекстом** для любой задачи в этом репозитории. AI-агент должен строго следовать этим правилам.

## 1. Архитектура проекта (Лендинг + PWA)
* Корневой маршрут `/` (page.tsx) — это десктопный и мобильный **SEO-лендинг**. Он должен быть оптимизирован для поисковиков.
* PWA-приложение начинается с маршрута `/catalog`. В настройках `manifest.json` параметр `start_url` должен быть строго равен `/catalog`.
* Внутри PWA используется нижняя панель навигации (Bottom Tab Bar) с 4 вкладками: **Каталог** (`/catalog`), **Рецепты** (`/recipes`), **Контакты** (`/contacts`), **Профиль** (`/profile`).

## 2. Общие принципы вайб-кодинга
* **Изучение перед изменением:** Перед написанием нового кода или созданием компонента проанализируй существующую структуру в `/src/components` и `/src/hooks`. Не создавай дубликаты.
* **Без самодеятельности:** Не изменяй публичные интерфейсы, архитектуру БД и структуру роутинга без предварительного предупреждения и согласования с пользователем.
* **Объяснение удалений:** Если удаляешь старый код, в комментариях к ответу коротко обоснуй причину.
* **Принцип малых шагов:** Не пытайся написать всю систему целиком за один промпт. Реализуй функционал поэтапно (например: сначала UI карточки -> затем подключение БД -> затем логика состояний).

## 3. Работа с базой данных (Supabase)
* **Миграции обязательны:** Любое изменение структуры БД сначала предлагается в виде SQL-скрипта. Не используй интерфейс Supabase Dashboard для внесения изменений в обход миграций, чтобы не терять историю версий.
* **RLS (Row Level Security):** При создании новой таблицы ВСЕГДА пиши RLS-политики. Указывай, кто может читать данные, а кто — редактировать.

## 4. Требования к UI, UX и SEO
* **Mobile-First:** Вся верстка изначально пишется под мобильные устройства (Tailwind CSS).
* **Состояния:** При написании компонентов, работающих с сетью, обязательно обрабатывай 3 состояния: загрузка (`isLoading`), ошибка (`isError`), пустое состояние (`isEmpty`).
* **SEO & Schema.org:** Для страниц товаров, статей (рецептов) и контактов внедряй JSON-LD микроразметку.
* **PWA ограничения:** Избегай механик, которые плохо работают без интернета. Если данные не загрузились, показывай кэшированную версию или заглушку "Нет подключения". На странице контактов предусмотри fallback для Яндекс.Карт, если нет сети.

## 5. Формат ответов AI
* В начале ответа указывай, **какие файлы** будут затронуты или созданы.
* После внесения изменений сообщай о возможных **побочных эффектах** для других модулей.
* Если тебе не хватает вводных данных для реализации логики (например, непонятен дизайн или структура данных) — **ОСТАНОВИСЬ и задай вопрос**. Не выдумывай бизнес-правила самостоятельно.
